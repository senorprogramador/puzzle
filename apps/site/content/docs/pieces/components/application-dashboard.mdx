Application sections provide structure for product and administrative interfaces. The consuming application owns authorization, data loading, mutations, persistence, and routing.

<Badge content="Beta" color="info" /> **API maturity: Beta.**

## Components

| Component | Purpose | Reference |
| --- | --- | --- |
| Dashboard Overview | Compose summary data, metrics, charts, and widgets. | [Dashboard](/docs/pieces/components/dashboard) |
| Activity | Show actor/action records with optional grouping and filters. | [Activity](/docs/pieces/components/activity) |
| Onboarding | Present application-controlled setup steps and progress. | [Onboarding](/docs/pieces/components/onboarding) |
| Empty State | Explain empty, success, and error states. | [Empty State](/docs/pieces/components/empty-state) |
| Settings | Arrange groups, controls, navigation, and actions. | [Settings](/docs/pieces/components/settings) |
| Project | Present project metadata, members, status, and progress. | [Project](/docs/pieces/components/project) |
| Dashboard Navigation | Compose application navigation and user menus. | [Dashboard Navigation](/docs/pieces/components/navigation) |
| Data Display | Reuse metrics, comparisons, activity, and empty states. | [Data Display](/docs/pieces/components/data-display) |
| Feedback | Present notifications, errors, and confirmation actions. | [Feedback](/docs/pieces/components/feedback) |

## Accessibility and state ownership

Use landmarks and heading levels appropriate to the surrounding page. Preserve
native keyboard behavior for forms and tabs; ensure loading/success/error
updates are announced. Every example here keeps business state in its caller.
The layouts use responsive CSS and semantic Puzzle Theme tokens.
