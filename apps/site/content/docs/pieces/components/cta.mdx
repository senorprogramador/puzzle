`CTASection` composes a message, optional media, actions, and custom children. It does not implement a newsletter form, download, trial, contact flow, or application behavior; consumers provide those elements.

<Badge content="Beta" color="primary" /> **API maturity: Beta.**

## Installation

```tsx
import { CTASection } from "@puzzle-ui/pieces";
```

## API

| Prop | Type | Description |
| --- | --- | --- |
| `variant` | `CTAVariant` | Selects one of sixteen call-to-action presentations; defaults to `centered`. |
| `title` / `description` / `eyebrow` | `ReactNode` | Shared section heading content. |
| `primaryAction` / `secondaryAction` | `ReactNode` | Consumer-provided next steps. |
| `media` | `ReactNode` | Optional consumer-provided media. |
| `children` | `ReactNode` | Additional composable content such as a form. |
| Shared section props | `SectionRootProps` | Semantic root, theme, native attributes, width, and spacing. |


### Required and default values

Requiredness follows the exported TypeScript type. A dash means no component-level default is applied; variant-specific requirements are described in the API table above.

| Prop | Required | Default |
| --- | --- | --- |
| `variant` | No | `"centered"` |
| `media` | No | — |
| `primaryAction` | No | — |
| `secondaryAction` | No | — |
## Usage

```tsx
<CTASection
  variant="trial"
  title="Ready to get started?"
  description="Try the workflow with your team."
  primaryAction={<a href="/signup">Start a trial</a>}
  secondaryAction={<a href="/docs">Read the guide</a>}
/>
```

The action slots are omitted when not supplied. Provide links, buttons, forms, and their loading/error behavior from the consuming application.

## Accessibility

Use descriptive action names and maintain a logical heading level. If a form is passed through `children`, provide its own labels, validation messages, and submission feedback.

## Customization

Use the component's `className` and documented slots to adapt the composition. Prefer a caller-provided `ReactNode` for media, actions, or controls rather than adding domain behavior to the section.

```tsx
import type { ComponentProps } from "react";
import { CTASection } from "@puzzle-ui/pieces";

type CTASectionProps = ComponentProps<typeof CTASection>;

export function CustomizedSection(props: CTASectionProps) {
  return <CTASection {...props} className={[props.className, "brand-section"].filter(Boolean).join(" ")} />;
}
```

## Responsive behavior

Use the preview device selector to review mobile, tablet, and desktop widths. The built-in variant controls section structure; ensure application-provided media, form controls, and children can shrink or wrap without horizontal overflow. Use the existing responsive breakpoints in scoped CSS when the consuming layout needs a product-specific adjustment.

## Theme support

The section consumes semantic variables from `@puzzle-ui/theme` and inherits active or scoped themes. Wrap the application with `Theme`, and use semantic roles such as text, surface, border, and primary for local overrides. Avoid hard-coded colors, spacing, radii, and shadows.

```css
.brand-section {
  color: var(--puzzle-color-text);
  background: var(--puzzle-color-surface);
  border-color: var(--puzzle-color-border);
}
```

## Composition

Compose this section with the UI primitives named in its API and use the documented slots for consumer-owned controls or media. Keep data fetching, routing, validation, permissions, and persistence in the application. The `children` slot is intended for additional content that belongs with this section, not as a substitute for its typed data model.

## TypeScript example

The package exports this component from its root. Derive a wrapper's exact prop type from the public component rather than widening it:

```tsx
import type { ComponentProps } from "react";
import { CTASection } from "@puzzle-ui/pieces";

type CTASectionProps = ComponentProps<typeof CTASection>;

export function SectionWrapper(props: CTASectionProps) {
  return <CTASection {...props} />;
}
```

## Framework compatibility

The section is router-independent. Static compositions can be server-rendered; place callback-driven interactions in the framework's client boundary. See [Next.js and TanStack Start integration](/docs/pieces/framework-integration) for runnable framework examples and SSR guidance.
