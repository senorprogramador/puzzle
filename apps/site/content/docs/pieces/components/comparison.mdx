`ComparisonSection` compares consumer-provided options and feature values. Each option has a stable ID and title; each feature has an ID, label, and values keyed by option ID.

<Badge content="Beta" color="primary" /> **API maturity: Beta.**

## Installation

```tsx
import {
  ComparisonSection,
  type ComparisonFeature,
  type ComparisonOption,
} from "@puzzle-ui/pieces";
```

## Variant previews

Table variants use semantic row/column headers and boolean values are labeled as included or not included. The interactive variant exposes a native radio group. On narrow screens the table scrolls within a labeled, keyboard-focusable viewport rather than widening the page.

## API

| Prop | Type | Description |
| --- | --- | --- |
| `variant` | `ComparisonVariant` | Selects one of twelve comparison compositions; defaults to `table`. |
| `options` | `readonly ComparisonOption[]` | Options with stable `id`, required `title`, and optional description/action. |
| `features` | `readonly ComparisonFeature[]` | Rows with stable `id`, label, and a `values` record keyed by option ID. |
| `highlightedOptionId` | `string` | Option emphasized in supported layouts. |
| `comparisonLabel` | `string` | Accessible label for the table viewport and table caption. |
| `selectedOptionId` | `string` | Controlled selection for `variant="interactive"`. |
| `defaultSelectedOptionId` | `string` | Initial uncontrolled selection for `variant="interactive"`. |
| `onSelectionChange` | `(optionId: string) => void` | Selection callback for `variant="interactive"`. |
| Shared section props | `SectionRootProps` and heading props | Semantic root, theme, native attributes, heading, actions, and children. |

Feature values may be booleans, strings, numbers, or React nodes. Undefined values render as `Not provided`. Selection state remains local unless controlled; no pricing or billing logic is included.


### Required and default values

Requiredness follows the exported TypeScript type. A dash means no component-level default is applied; variant-specific requirements are described in the API table above.

| Prop | Required | Default |
| --- | --- | --- |
| `variant` | No | `"table"` |
| `selectedOptionId` | No | — |
| `defaultSelectedOptionId` | No | — |
| `onSelectionChange` | No | — |
| `options` | Yes | — |
| `features` | Yes | — |
| `highlightedOptionId` | No | — |
| `comparisonLabel` | No | `"Feature comparison"` |
## Usage

```tsx
<ComparisonSection
  variant="interactive"
  title="Choose a plan"
  options={[
    { id: "starter", title: "Starter" },
    { id: "team", title: "Team", featured: true },
  ]}
  features={[
    { id: "seats", label: "Team members", values: { starter: 3, team: 20 } },
    { id: "support", label: "Priority support", values: { starter: false, team: true } },
  ]}
  defaultSelectedOptionId="starter"
/>
```

An empty option collection omits the comparison structure. Use unique option and feature IDs, and ensure each feature's value keys match the option IDs.

## Accessibility

Tables include a caption, column headers, and row headers. Interactive table options use native radio controls. The scroll viewport is keyboard focusable and labeled so users can reach off-screen columns without page-level horizontal overflow.

## Customization

Use the component's `className` and documented slots to adapt the composition. Prefer a caller-provided `ReactNode` for media, actions, or controls rather than adding domain behavior to the section.

```tsx
import type { ComponentProps } from "react";
import { ComparisonSection } from "@puzzle-ui/pieces";

type ComparisonSectionProps = ComponentProps<typeof ComparisonSection>;

export function CustomizedSection(props: ComparisonSectionProps) {
  return <ComparisonSection {...props} className={[props.className, "brand-section"].filter(Boolean).join(" ")} />;
}
```

## Responsive behavior

Use the preview device selector to review mobile, tablet, and desktop widths. The built-in variant controls section structure; ensure application-provided media, form controls, and children can shrink or wrap without horizontal overflow. Use the existing responsive breakpoints in scoped CSS when the consuming layout needs a product-specific adjustment.

## Theme support

The section consumes semantic variables from `@puzzle-ui/theme` and inherits active or scoped themes. Wrap the application with `Theme`, and use semantic roles such as text, surface, border, and primary for local overrides. Avoid hard-coded colors, spacing, radii, and shadows.

```css
.brand-section {
  color: var(--puzzle-color-text);
  background: var(--puzzle-color-surface);
  border-color: var(--puzzle-color-border);
}
```

## Composition

Compose this section with the UI primitives named in its API and use the documented slots for consumer-owned controls or media. Keep data fetching, routing, validation, permissions, and persistence in the application. The `children` slot is intended for additional content that belongs with this section, not as a substitute for its typed data model.

## TypeScript example

The package exports this component from its root. Derive a wrapper's exact prop type from the public component rather than widening it:

```tsx
import type { ComponentProps } from "react";
import { ComparisonSection } from "@puzzle-ui/pieces";

type ComparisonSectionProps = ComponentProps<typeof ComparisonSection>;

export function SectionWrapper(props: ComparisonSectionProps) {
  return <ComparisonSection {...props} />;
}
```
