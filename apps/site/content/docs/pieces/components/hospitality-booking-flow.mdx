This example composes existing and new Pieces for an accommodation booking
journey. The search form, rates, summary, and house rules all use supplied
props. The demo has no booking backend, availability calculation, price
calculation, database, or payment flow.

## Composition

1. `AvailabilitySearchSection` presents dates, guest counts, and an optional
   accommodation choice. Its callback hands the values to application code.
2. `RatePlansSection` displays the rate data returned by the application's
   external source. It does not derive weekly prices from nightly prices.
3. `StaySummarySection` displays the supplied guest/date details, price lines,
   and total. It does not calculate nights or sum the breakdown.
4. `HouseRulesSection` presents property terms provided by the owner or app.
5. Existing [Accommodation Details](/docs/pieces/components/accommodation-details),
   [Gallery](/docs/pieces/components/gallery-section), and
   [Testimonials](/docs/pieces/components/testimonials) can be composed around
   the booking information where appropriate.

## Integration boundary

The application owns the availability provider, validation beyond the
component's local date/guest checks, the source of each rate, currency
conversion, price arithmetic, reservation state, external navigation, and
payment. Supply explicit locale and time-zone values when server-rendered date
and price strings must match the browser.
