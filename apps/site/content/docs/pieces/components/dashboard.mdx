Dashboard compositions provide reusable structure for product and admin interfaces without coupling presentation to a router, data model, or framework.

<Badge content="Stable" color="primary" /> **API maturity: Stable.** The documented API is covered by package tests and is intended to remain backward-compatible within a major version. This is an API commitment, not a guarantee of production readiness in every application.

## Installation

Import the dashboard components from Puzzle Pieces:

```tsx
import {
  DashboardActivityFeed,
  DashboardHeader,
  DashboardProgressCard,
  DashboardShell,
  DashboardStatCard,
  DashboardStatGroup,
} from "@puzzle-ui/pieces";
```

## Dashboard overview

`DashboardOverviewSection` composes a labelled dashboard landmark with summary data, metric cards, a date-range slot, actions, optional charts, and arbitrary widgets. Metric trends can use `DashboardStatCard`; chart rendering remains the responsibility of the application because Pieces does not include a chart engine.

## Accessibility and responsive behavior

- The header uses a level-one heading; place only one `DashboardHeader` on a page.
- `DashboardStatGroup` is a labelled region. Cards expose their labels as headings.
- Loading cards expose `aria-busy` and hide decorative placeholders from assistive technology.
- Activity feeds use an ordered list and native `<time>` elements; provide stable item IDs and machine-readable `dateTime` values when available.
- Progress cards use the native `<progress>` element. Provide a value from `0` to `100`.
- Shell landmarks and sidebar labels are semantic; supply meaningful labels when composing multiple landmarks.
- Layouts adapt to narrow viewports and use Puzzle theme tokens for colors, spacing, borders, and typography.

## API

| Component                  | Props                                                                                                                                                                                                                |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DashboardOverviewSection` | `title` (required), `description`, `eyebrow`, `variant` (defaults to `grid`), `summary`, `metrics`, `charts` (caller-provided; no chart engine), `dateRange`, `actions`, `children`, `loading`, `error`, `className` |
| `DashboardHeader`          | `title` (required), `eyebrow`, `description`, `actions`, `className`                                                                                                                                                 |
| `DashboardStatCard`        | `label` (required), `value`, `description`, `icon`, `trend` (`value`, `label`, optional `direction`), `action`, `loading`, `className`                                                                               |
| `DashboardStatGroup`       | `children` (required), `label`, `columns` (`2`, `3`, or `4`), `className`                                                                                                                                            |
| `DashboardActivityFeed`    | `items` (required; each has `id`, `description`, `timestamp`, optional `dateTime`, `avatar`, `href`), `title`, `emptyState`, `renderItem`, `className`                                                               |
| `DashboardProgressCard`    | `title` (required), `value` (required, from `0` to `100`), `description`, `status`, `action`, `className`                                                                                                            |
| `DashboardShell`           | `children` (required), `sidebar`, `topbar`, `sidebarLabel`, `className`                                                                                                                                              |

All content and action slots accept React nodes. Callbacks and data retrieval belong to the application.

### Required and default values

Requiredness follows the exported TypeScript type. A dash means no component-level default is applied; variant-specific requirements are described in the API table above.

| Prop          | Required | Default  |
| ------------- | -------- | -------- |
| `title`       | Yes      | —        |
| `description` | No       | —        |
| `eyebrow`     | No       | —        |
| `variant`     | No       | `"grid"` |
| `summary`     | No       | —        |
| `metrics`     | No       | —        |
| `charts`      | No       | —        |
| `dateRange`   | No       | —        |
| `actions`     | No       | —        |
| `children`    | No       | —        |
| `loading`     | No       | `false`  |
| `error`       | No       | —        |
| `className`   | No       | —        |

## Customization

Use the component's `className` and documented slots to adapt the composition. Prefer a caller-provided `ReactNode` for media, actions, or controls rather than adding domain behavior to the section.

```tsx
import type { ComponentProps } from "react";
import { DashboardOverviewSection } from "@puzzle-ui/pieces";

type DashboardOverviewSectionProps = ComponentProps<
  typeof DashboardOverviewSection
>;

export function CustomizedSection(props: DashboardOverviewSectionProps) {
  return (
    <DashboardOverviewSection
      {...props}
      className={[props.className, "brand-section"].filter(Boolean).join(" ")}
    />
  );
}
```

## Theme support

The section consumes semantic variables from `@puzzle-ui/theme` and inherits active or scoped themes. Wrap the application with `Theme`, and use semantic roles such as text, surface, border, and primary for local overrides. Avoid hard-coded colors, spacing, radii, and shadows.

```css
.brand-section {
  color: var(--puzzle-color-text);
  background: var(--puzzle-color-surface);
  border-color: var(--puzzle-color-border);
}
```

## Composition

Compose this section with the UI primitives named in its API and use the documented slots for consumer-owned controls or media. Keep data fetching, routing, validation, permissions, and persistence in the application. The `children` slot is intended for additional content that belongs with this section, not as a substitute for its typed data model.

## TypeScript example

The package exports this component from its root. Derive a wrapper's exact prop type from the public component rather than widening it:

```tsx
import type { ComponentProps } from "react";
import { DashboardOverviewSection } from "@puzzle-ui/pieces";

type DashboardOverviewSectionProps = ComponentProps<
  typeof DashboardOverviewSection
>;

export function SectionWrapper(props: DashboardOverviewSectionProps) {
  return <DashboardOverviewSection {...props} />;
}
```

## Framework compatibility

The section is router-independent. Static compositions can be server-rendered; place callback-driven interactions in the framework's client boundary. See [Next.js and TanStack Start integration](/docs/pieces/framework-integration) for runnable framework examples and SSR guidance.
