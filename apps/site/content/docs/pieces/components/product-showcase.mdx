`ProductShowcaseSection` presents consumer-provided product media and supporting copy. Its layouts range from single-screen browser and device frames to interactive tabs, galleries, and a controlled carousel.

<Badge content="Stable" color="primary" /> **API maturity: Stable.** The documented API is covered by package tests and is intended to remain backward-compatible within a major version. This is an API commitment, not a guarantee of production readiness in every application.

## Installation

```tsx
import {
  ProductShowcaseSection,
  type ProductShowcaseItem,
} from "@puzzle-ui/pieces";
```

## API reference

| Prop | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `items` | `readonly ProductShowcaseItem[]` | Yes | — | Screens or recordings to display; IDs must be unique. |
| `variant` | `ProductShowcaseVariant` | No | `split` | Presentation layout. |
| Shared section props | `MarketingSectionBaseProps` | No | — | Header, root element, width/theme, native attributes, actions, and children. |

`ProductShowcaseSectionProps<C>` combines the shared section props with
`variant` and `items`. The item data model is:

| Property | Type | Description |
| --- | --- | --- |
| `items` | `readonly ProductShowcaseItem[]` | Product screens and their accompanying content. |
| `ProductShowcaseItem.id` | `string` | Stable, unique item ID; required by tabs and lists. |
| `ProductShowcaseItem.title` | `ReactNode` | Item heading and default browser-frame label. |
| `ProductShowcaseItem.media` | `ReactNode` | Consumer-provided screenshot, video, or other media. |
| `ProductShowcaseItem.frame` | `"none" \| "browser" \| "desktop" \| "mobile"` | Optional frame override for an item. |
| `ProductShowcaseItem.caption` | `ReactNode` | Optional media caption. |
| `ProductShowcaseItem.annotations` | `readonly ProductShowcaseAnnotation[]` | Optional native disclosure annotations. |
| `ProductShowcaseItem.description` | `ReactNode` | Supporting product explanation. |
| `ProductShowcaseItem.action` | `ReactNode` | Optional action supplied by the consumer. |
| `ProductShowcaseItem.featured` | `boolean` | Emphasizes an item in layouts that support a featured item. |

`variant` defaults to `split`. Shared section props include the semantic root element, header content, section theme, native attributes, and children.

## Usage

```tsx
const items: ProductShowcaseItem[] = [
  {
    id: "workspace",
    title: "Keep launches in view",
    description: "See owners, milestones, and decisions together.",
    media: <img src="/screens/launch.png" alt="Launch dashboard with milestones" />,
    caption: "Launch dashboard",
    annotations: [
      {
        id: "owners",
        label: "Owners",
        description: "Review the person responsible for each milestone.",
      },
    ],
  },
  {
    id: "workflows",
    title: "Bring context together",
    media: <img src="/screens/workflows.png" alt="Workflow builder screen" />,
  },
];

<ProductShowcaseSection
  variant="tabs"
  title="A clear view from brief to launch"
  items={items}
/>;
```

`browser`, `desktop`, and `mobile` apply a default frame to each item. An item's
`frame` can override that default. The `carousel` variant uses the UI Carousel,
showing one item on mobile and tablet and two on desktop, with caret controls
beside the content and a page indicator below. It does not auto-advance. The
`interactive` variant renders annotations as native `<details>` disclosures.

## Accessibility

Provide meaningful alternative text for informative screenshots and captions where they add context. Decorative media should use an empty alternative. Tabs use the UI package's keyboard-operable `Tabs`; the carousel buttons have accessible names and disabled states. Annotation disclosures use native keyboard behavior.

The component does not fetch, create, or infer screenshots. It is server-renderable and does not access browser APIs during render.

## Responsive behavior and theme support

Device frames remain within the section width, galleries and split layouts
reflow on mobile, and the carousel uses its explicit previous/next controls.
Use the Preview device selector to check each layout at mobile, tablet, and
desktop widths.

The section consumes semantic Puzzle Theme tokens. Wrap it in `Theme` or a
scoped theme to inherit the application's palette and typography; use
`className` for local customization instead of hard-coding theme colors.

## Customization

Use the component's `className` and documented slots to adapt the composition. Prefer a caller-provided `ReactNode` for media, actions, or controls rather than adding domain behavior to the section.

```tsx
import type { ComponentProps } from "react";
import { ProductShowcaseSection } from "@puzzle-ui/pieces";

type ProductShowcaseSectionProps = ComponentProps<typeof ProductShowcaseSection>;

export function CustomizedSection(props: ProductShowcaseSectionProps) {
  return <ProductShowcaseSection {...props} className={[props.className, "brand-section"].filter(Boolean).join(" ")} />;
}
```

## Composition

Compose this section with the UI primitives named in its API and use the documented slots for consumer-owned controls or media. Keep data fetching, routing, validation, permissions, and persistence in the application. The `children` slot is intended for additional content that belongs with this section, not as a substitute for its typed data model.
