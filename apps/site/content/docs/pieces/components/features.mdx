`FeaturesSection` renders product capabilities from consumer-provided items. Each feature has a stable `id` and `title`, with optional description, icon, media, action, nested content, and featured emphasis.

<Badge content="Beta" color="primary" /> **API maturity: Beta.**

## Installation

```tsx
import { FeaturesSection, type FeatureItem } from "@puzzle-ui/pieces";
```

## Variant previews

The `tabs` and `accordion` variants reuse the corresponding accessible UI primitives. Tabs are keyboard-operable; accordion expansion follows the UI Accordion behavior.

## API

| Prop                   | Type                                 | Description                                                                       |
| ---------------------- | ------------------------------------ | --------------------------------------------------------------------------------- |
| `variant`              | `FeaturesVariant`                    | Selects one of the seventeen feature layouts; defaults to `grid`.                 |
| `items`                | `readonly FeatureItem[]`             | Feature data with stable `id`, required `title`, and optional presentation slots. |
| `FeatureItem.icon`     | `ReactNode`                          | Consumer-provided icon node.                                                      |
| `FeatureItem.media`    | `ReactNode`                          | Optional image, video, or other media.                                            |
| `FeatureItem.content`  | `ReactNode`                          | Additional item content.                                                          |
| `FeatureItem.action`   | `ReactNode`                          | Optional consumer-provided action.                                                |
| `FeatureItem.featured` | `boolean`                            | Emphasizes an item in layouts that support it.                                    |
| Shared section props   | `SectionRootProps` and heading props | Semantic root, theme, native attributes, heading, actions, and children.          |


### Required and default values

Requiredness follows the exported TypeScript type. A dash means no component-level default is applied; variant-specific requirements are described in the API table above.

| Prop | Required | Default |
| --- | --- | --- |
| `variant` | No | `"grid"` |
| `items` | Yes | — |
## Usage

```tsx
<FeaturesSection
  variant="tabs"
  title="Built for focused teams"
  items={[
    {
      id: "automation",
      title: "Automate routine work",
      description: "Spend more time on important decisions.",
      media: <img src="/automation.png" alt="Automation settings" />,
    },
    { id: "insights", title: "Understand progress" },
  ]}
/>
```

An empty collection omits its list or interactive control. The `tabs` composition uses item IDs as tab IDs; keep IDs stable and unique. Media must have suitable alternatives when it conveys information.

## Accessibility

Interactive tabs and accordions use UI keyboard and ARIA behavior. Keep the shared section heading at an appropriate page level, and ensure the item title hierarchy remains meaningful. Decorative icons should be hidden from assistive technology by their consumer-provided markup.

## Customization

Use the component's `className` and documented slots to adapt the composition. Prefer a caller-provided `ReactNode` for media, actions, or controls rather than adding domain behavior to the section.

```tsx
import type { ComponentProps } from "react";
import { FeaturesSection } from "@puzzle-ui/pieces";

type FeaturesSectionProps = ComponentProps<typeof FeaturesSection>;

export function CustomizedSection(props: FeaturesSectionProps) {
  return <FeaturesSection {...props} className={[props.className, "brand-section"].filter(Boolean).join(" ")} />;
}
```

## Responsive behavior

Use the preview device selector to review mobile, tablet, and desktop widths. The built-in variant controls section structure; ensure application-provided media, form controls, and children can shrink or wrap without horizontal overflow. Use the existing responsive breakpoints in scoped CSS when the consuming layout needs a product-specific adjustment.

## Theme support

The section consumes semantic variables from `@puzzle-ui/theme` and inherits active or scoped themes. Wrap the application with `Theme`, and use semantic roles such as text, surface, border, and primary for local overrides. Avoid hard-coded colors, spacing, radii, and shadows.

```css
.brand-section {
  color: var(--puzzle-color-text);
  background: var(--puzzle-color-surface);
  border-color: var(--puzzle-color-border);
}
```

## Composition

Compose this section with the UI primitives named in its API and use the documented slots for consumer-owned controls or media. Keep data fetching, routing, validation, permissions, and persistence in the application. The `children` slot is intended for additional content that belongs with this section, not as a substitute for its typed data model.

## TypeScript example

The package exports this component from its root. Derive a wrapper's exact prop type from the public component rather than widening it:

```tsx
import type { ComponentProps } from "react";
import { FeaturesSection } from "@puzzle-ui/pieces";

type FeaturesSectionProps = ComponentProps<typeof FeaturesSection>;

export function SectionWrapper(props: FeaturesSectionProps) {
  return <FeaturesSection {...props} />;
}
```
