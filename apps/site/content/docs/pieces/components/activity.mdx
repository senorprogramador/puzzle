## Filtering

Filter the source data in your application and pass the result as `items`. The example filters by category and keeps the selected filter in caller-owned state.

<Preview fit="device" code={`<ActivitySection items={filteredItems} variant="grouped" />`}>

Supported variants: `timeline`, `list`, `feed`, `grouped`, `cards`, `compact`, `avatars`, `audit`, `split`, and `horizontal`.

## Accessibility and API

- Each section is labelled by its heading. Events use ordered lists, semantic `<time>` elements, and native links when `href` is provided.
- Supply stable unique item IDs. `group` controls grouping and `groupLabel` supplies the displayed heading.
- `category` and `metadata` are application-defined fields for filtering and supplementary information.
- Empty data uses the shared `EmptyStatePanel` composition. Supply a custom `emptyState` message when the default is not appropriate.
- Use `renderItem` only when the default actor/action/time/metadata presentation does not meet the product's needs.

`ActivityItem` supports `id`, `actor`, `action`, `timestamp`, `dateTime`, `icon`, `description`, `metadata`, `group`, `groupLabel`, `category`, and `href`.
