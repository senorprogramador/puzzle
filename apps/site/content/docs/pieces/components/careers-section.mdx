`CareersSection` displays application-owned job data and benefits. It can group opportunities by department or location and provides an empty state when no openings are supplied.

<Badge content="Stable" color="primary" /> **API maturity: Stable.** The documented API is covered by package tests and is intended to remain backward-compatible within a major version. This is an API commitment, not a guarantee of production readiness in every application.

## Installation

```tsx
import {
  CareersSection,
  type BusinessCareerPosition,
  type CareersSectionVariant,
} from "@puzzle-ui/pieces";
```

## API

| Prop | Type | Description |
| --- | --- | --- |
| `variant` | `CareersSectionVariant` | `list` (default), `grid`, `featured`, `departments`, `culture`, `split`, `benefits`, `editorial`, `cards`, `locations`, `compact`, or `hiring`. |
| `positions` | `readonly BusinessCareerPosition[]` | Openings with unique ID and title; optional department, location, employment type, description, application link, and featured state. |
| `benefits` | `readonly BusinessBenefit[]` | Optional benefit items with unique IDs and titles. |
| `culture` | `ReactNode` | Optional company culture content. |
| `emptyState` | `ReactNode` | Optional replacement for the default no-openings message. |
| `featuredPosition` | `BusinessCareerPosition \| string` | Optional position object or ID promoted in the featured layouts. |
| Shared section props | `MarketingSectionBaseProps` | Heading, actions, root element, native section attributes, and children. |


### Required and default values

Requiredness follows the exported TypeScript type. A dash means no component-level default is applied; variant-specific requirements are described in the API table above.

| Prop | Required | Default |
| --- | --- | --- |
| `variant` | No | `"list"` |
| `positions` | Yes | — |
| `benefits` | No | empty array |
| `culture` | No | — |
| `emptyState` | No | `"There are no open positions right now."` |
| `featuredPosition` | No | — |
## Usage

```tsx
<CareersSection
  variant="departments"
  title="Work with us"
  positions={[
    {
      id: "designer",
      title: "Senior product designer",
      department: "Product",
      location: "Amsterdam",
      employmentType: "Full-time",
      description: "Shape tools for growing teams.",
      href: "/careers/product-designer",
    },
  ]}
  benefits={[
    { id: "learning", title: "Learning budget" },
    { id: "flexibility", title: "Flexible work" },
  ]}
/>
```

## Accessibility and rendering

Position titles and application links are semantic headings and native anchors. Department and location groupings retain their heading structure. The default empty state remains visible when `positions` is empty, including grouped layouts. Keep IDs unique and stable; the component validates supplied positions and benefits. There is no application workflow or backend, and rendering is server compatible.

## Customization

Use the component's `className` and documented slots to adapt the composition. Prefer a caller-provided `ReactNode` for media, actions, or controls rather than adding domain behavior to the section.

```tsx
import type { ComponentProps } from "react";
import { CareersSection } from "@puzzle-ui/pieces";

type CareersSectionProps = ComponentProps<typeof CareersSection>;

export function CustomizedSection(props: CareersSectionProps) {
  return <CareersSection {...props} className={[props.className, "brand-section"].filter(Boolean).join(" ")} />;
}
```

## Responsive behavior

Use the preview device selector to review mobile, tablet, and desktop widths. The built-in variant controls section structure; ensure application-provided media, form controls, and children can shrink or wrap without horizontal overflow. Use the existing responsive breakpoints in scoped CSS when the consuming layout needs a product-specific adjustment.

## Theme support

The section consumes semantic variables from `@puzzle-ui/theme` and inherits active or scoped themes. Wrap the application with `Theme`, and use semantic roles such as text, surface, border, and primary for local overrides. Avoid hard-coded colors, spacing, radii, and shadows.

```css
.brand-section {
  color: var(--puzzle-color-text);
  background: var(--puzzle-color-surface);
  border-color: var(--puzzle-color-border);
}
```

## Composition

Compose this section with the UI primitives named in its API and use the documented slots for consumer-owned controls or media. Keep data fetching, routing, validation, permissions, and persistence in the application. The `children` slot is intended for additional content that belongs with this section, not as a substitute for its typed data model.

## TypeScript example

```tsx
import type { ComponentProps } from "react";
import { CareersSection } from "@puzzle-ui/pieces";

type CareersSectionProps = ComponentProps<typeof CareersSection>;

export function SectionWrapper(props: CareersSectionProps) {
  return <CareersSection {...props} />;
}
```
