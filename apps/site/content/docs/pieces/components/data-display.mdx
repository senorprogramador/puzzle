Data display compositions present application-provided values without owning data fetching, formatting, or business rules. Shared dashboard patterns are re-exported here rather than implemented twice.

<Badge content="Stable" color="primary" /> **API maturity: Stable.** The documented API is covered by package tests and is intended to remain backward-compatible within a major version. This is an API commitment, not a guarantee of production readiness in every application.

## Installation

```tsx
import {
  ActivityTimeline,
  EmptyStatePanel,
  MetricComparison,
  ProgressOverview,
  StatCard,
  StatGroup,
} from "@puzzle-ui/pieces";
```

`StatCard`, `StatGroup`, `ActivityTimeline`, and `ProgressOverview` are aliases of `DashboardStatCard`, `DashboardStatGroup`, `DashboardActivityFeed`, and `DashboardProgressCard`. Their APIs and behavior are identical.

## Accessibility and responsive behavior

- Comparison values use a definition list with explicit labels.
- Empty states use a labelled section and heading; provide useful action names.
- Activity timelines and progress indicators retain the native semantics documented on the Dashboard page.
- Grid and comparison layouts adapt at narrow widths and use Puzzle theme tokens.

## API

| Component | Props |
| --- | --- |
| `StatCard` | Same as `DashboardStatCard`: `label`, `value`, `description`, `icon`, `trend`, `action`, `loading`, `className` |
| `StatGroup` | Same as `DashboardStatGroup`: `children`, `label`, `columns`, `className` |
| `ActivityTimeline` | Same as `DashboardActivityFeed`: `items`, `title`, `emptyState`, `renderItem`, `className` |
| `ProgressOverview` | Same as `DashboardProgressCard`: `title`, `value`, `description`, `status`, `action`, `className` |
| `MetricComparison` | `title`, `primaryLabel`, `primaryValue`, `comparisonLabel`, `comparisonValue` (required), `description`, `className` |
| `EmptyStatePanel` | `title` (required), `description`, `illustration`, `action`, `className` |
