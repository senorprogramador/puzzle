`StatsSection` presents consumer-provided values without requiring an external data source. Values may be numbers or formatted strings, with optional prefixes, suffixes, descriptions, trend labels, progress, and emphasis.

<Badge content="Beta" color="primary" /> **API maturity: Beta.**

## Installation

```tsx
import { StatsSection, type StatItem } from "@puzzle-ui/pieces";
```

## Variant previews

The `animated` variant counts numeric values after mount. It renders the final value immediately when `prefers-reduced-motion` is enabled. String values remain unchanged.

## API

| Prop | Type | Description |
| --- | --- | --- |
| `variant` | `StatsVariant` | Selects one of twelve metric layouts; defaults to `grid`. |
| `items` | `readonly StatItem[]` | Data with stable `id`, `label`, and required `value`. |
| `StatItem.prefix` / `suffix` | `ReactNode` | Optional content displayed beside the value. |
| `StatItem.trend` | `{ direction: "up" \| "down" \| "neutral"; label: ReactNode }` | Direction and consumer-supplied trend description. |
| `StatItem.progress` | `number` | Optional progress percentage, clamped to 0-100. |
| `StatItem.featured` | `boolean` | Emphasizes a metric in supported layouts. |
| Shared section props | `SectionRootProps` and heading props | Semantic root, theme, native attributes, heading, actions, and children. |


### Required and default values

Requiredness follows the exported TypeScript type. A dash means no component-level default is applied; variant-specific requirements are described in the API table above.

| Prop | Required | Default |
| --- | --- | --- |
| `variant` | No | `"grid"` |
| `items` | Yes | — |
## Usage

```tsx
<StatsSection
  variant="progress"
  title="Quarterly results"
  items={[
    { id: "uptime", label: "Uptime", value: 99.9, suffix: "%" },
    { id: "users", label: "Active users", value: 2400, progress: 75 },
  ]}
/>
```

Progress values outside 0-100 are clamped for display. Animated values do not use a live region, avoiding continuous announcements to assistive technology.

## Accessibility

Use clear labels and meaningful trend descriptions. Progress indicators receive an accessible name based on the string label or item ID. Reduced-motion preferences disable the counter animation.

## Customization

Use the component's `className` and documented slots to adapt the composition. Prefer a caller-provided `ReactNode` for media, actions, or controls rather than adding domain behavior to the section.

```tsx
import type { ComponentProps } from "react";
import { StatsSection } from "@puzzle-ui/pieces";

type StatsSectionProps = ComponentProps<typeof StatsSection>;

export function CustomizedSection(props: StatsSectionProps) {
  return <StatsSection {...props} className={[props.className, "brand-section"].filter(Boolean).join(" ")} />;
}
```

## Responsive behavior

Use the preview device selector to review mobile, tablet, and desktop widths. The built-in variant controls section structure; ensure application-provided media, form controls, and children can shrink or wrap without horizontal overflow. Use the existing responsive breakpoints in scoped CSS when the consuming layout needs a product-specific adjustment.

## Theme support

The section consumes semantic variables from `@puzzle-ui/theme` and inherits active or scoped themes. Wrap the application with `Theme`, and use semantic roles such as text, surface, border, and primary for local overrides. Avoid hard-coded colors, spacing, radii, and shadows.

```css
.brand-section {
  color: var(--puzzle-color-text);
  background: var(--puzzle-color-surface);
  border-color: var(--puzzle-color-border);
}
```

## Composition

Compose this section with the UI primitives named in its API and use the documented slots for consumer-owned controls or media. Keep data fetching, routing, validation, permissions, and persistence in the application. The `children` slot is intended for additional content that belongs with this section, not as a substitute for its typed data model.

## TypeScript example

The package exports this component from its root. Derive a wrapper's exact prop type from the public component rather than widening it:

```tsx
import type { ComponentProps } from "react";
import { StatsSection } from "@puzzle-ui/pieces";

type StatsSectionProps = ComponentProps<typeof StatsSection>;

export function SectionWrapper(props: StatsSectionProps) {
  return <StatsSection {...props} />;
}
```
