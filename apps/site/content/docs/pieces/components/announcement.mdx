`AnnouncementSection` displays a concise notice with optional icon and consumer-provided action. It supports a single message, a countdown, or independently dismissible messages. It does not own campaign routing, persistence, or scheduling.

<Badge content="Stable" color="primary" /> **API maturity: Stable.** The documented API is covered by package tests and is intended to remain backward-compatible within a major version. This is an API commitment, not a guarantee of production readiness in every application.

## Installation

```tsx
import { AnnouncementSection } from "@puzzle-ui/pieces";
```

## Variant previews

Every supported variant has an individual runnable preview. The dismiss control is keyboard operable; countdown mode requires a valid date string or `Date`.

## API

| Prop | Type | Description |
| --- | --- | --- |
| `variant` | `"bar" \| "dismissible" \| "centered" \| "split" \| "promotional" \| "countdown" \| "ticker" \| "multi-message" \| "floating" \| "minimal"` | Selects the presentation. Defaults to `bar`. |
| `message` | `ReactNode` | Content for a single announcement. |
| `icon` | `ReactNode` | Optional decorative icon for a single announcement. |
| `action` | `ReactNode` | Consumer-provided action for a single announcement. |
| `dismissible` | `boolean` | Enables the dismiss button. Defaults to true for the `dismissible` variant. |
| `dismissLabel` | `string` | Accessible name for the dismiss button. |
| `countdownTarget` | `Date \| string` | Required with `variant="countdown"`; invalid dates throw a `RangeError`. |
| `announcements` | `readonly AnnouncementItem[]` | Required with `variant="multi-message"`; each item needs a stable `id` and `message`. |
| Shared section props | `SectionRootProps` and heading props | Semantic root, theme, native attributes, optional heading, actions, and children. |


### Required and default values

Requiredness follows the exported TypeScript type. A dash means no component-level default is applied; variant-specific requirements are described in the API table above.

| Prop | Required | Default |
| --- | --- | --- |
| `variant` | No | `"bar"` |
| `countdownTarget` | Conditional | — |
| `announcements` | Conditional | empty array |
| `message` | No | — |
| `icon` | No | — |
| `action` | No | — |
| `dismissible` | No | — |
| `dismissLabel` | No | `"Dismiss announcement"` |
## Usage

```tsx
<AnnouncementSection
  variant="dismissible"
  message="A new collection is available."
  action={<a href="/collections">Explore the collection</a>}
/>
```

`multi-message` accepts `icon`, `action`, and `dismissLabel` per announcement item. Dismissed messages are removed for the current mounted instance; persistence is the consumer's responsibility. The `ticker` layout is horizontally scrollable and does not animate automatically.

## Accessibility

Dismiss controls are real buttons with an accessible name and normal keyboard behavior. Use meaningful action text, keep notice content concise, and do not place essential information only in a decorative icon. A countdown is exposed as a `time` element; it is not announced every second.

## Customization

Use the component's `className` and documented slots to adapt the composition. Prefer a caller-provided `ReactNode` for media, actions, or controls rather than adding domain behavior to the section.

```tsx
import type { ComponentProps } from "react";
import { AnnouncementSection } from "@puzzle-ui/pieces";

type AnnouncementSectionProps = ComponentProps<typeof AnnouncementSection>;

export function CustomizedSection(props: AnnouncementSectionProps) {
  return <AnnouncementSection {...props} className={[props.className, "brand-section"].filter(Boolean).join(" ")} />;
}
```

## Responsive behavior

Use the preview device selector to review mobile, tablet, and desktop widths. The built-in variant controls section structure; ensure application-provided media, form controls, and children can shrink or wrap without horizontal overflow. Use the existing responsive breakpoints in scoped CSS when the consuming layout needs a product-specific adjustment.

## Theme support

The section consumes semantic variables from `@puzzle-ui/theme` and inherits active or scoped themes. Wrap the application with `Theme`, and use semantic roles such as text, surface, border, and primary for local overrides. Avoid hard-coded colors, spacing, radii, and shadows.

```css
.brand-section {
  color: var(--puzzle-color-text);
  background: var(--puzzle-color-surface);
  border-color: var(--puzzle-color-border);
}
```

## Composition

Compose this section with the UI primitives named in its API and use the documented slots for consumer-owned controls or media. Keep data fetching, routing, validation, permissions, and persistence in the application. The `children` slot is intended for additional content that belongs with this section, not as a substitute for its typed data model.

## TypeScript example

The package exports this component from its root. Derive a wrapper's exact prop type from the public component rather than widening it:

```tsx
import type { ComponentProps } from "react";
import { AnnouncementSection } from "@puzzle-ui/pieces";

type AnnouncementSectionProps = ComponentProps<typeof AnnouncementSection>;

export function SectionWrapper(props: AnnouncementSectionProps) {
  return <AnnouncementSection {...props} />;
}
```
