CMS authoring Pieces compose admin interfaces from data and actions supplied by the host application. They do not fetch, authorize, validate, schedule, or persist content. Use the `@puzzle-ui/cms` and `@puzzle-ui/fullstack/cms/*` APIs on the server and client for those responsibilities.

## Boundaries and integration

Define the CMS schema and operations in the application/server layer; these Pieces accept caller-owned content projections and callbacks and do not call the CMS service. The host must authorize every operation, enforce tenant and revision checks, validate on the server, and use an explicit scheduler for scheduled publication.

CMS schemas are defined in application code; these Pieces do not register or persist runtime schemas. Pass only the presentation-safe collection data needed by the UI; keep access policies, lifecycle hooks, validators, secrets, and authorization decisions on the server. Pass `ContentEditor.renderField` to compose specialized inputs such as `MediaField` or `RelationshipField`. Pass `BlockEditor.renderBlock` to edit the configured fields for each serializable block type.

Use the CMS and Fullstack guides for verified persistence and lifecycle
operations. These Pieces remain presentation components; their callbacks do
not define server routes or client methods.

`PublishScheduler` converts local wall time using the selected timezone, reports nonexistent daylight-saving times, and chooses the earlier instant for an ambiguous repeated time. The server scheduler remains responsible for executing the returned publication job.
