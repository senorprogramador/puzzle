The hospitality surface composes existing Pieces and generic UI. It is a
presentation layer: applications supply all content, data, validation,
availability, prices, and actions. Start with a fit-for-purpose component
below, and reuse existing Hero, Gallery, Location, Testimonials, Resource,
Team, Services, and Product Grid components instead of building parallel
systems.

## Responsibility boundaries

- **Reviews:** the application supplies review text, dates, source, score, and
  any aggregate distribution. Pieces does not verify reviews or calculate
  averages.
- **Local guide:** distances and travel times are displayed as supplied.
  Pieces does not geocode, create maps, or calculate routes.
- **Services and vouchers:** prices and purchase destinations are supplied.
  Pieces does not provide checkout, voucher administration, or payment.
- **Availability and reservations:** Pieces can present forms and callbacks.
  The application or provider owns availability, confirmation, and
  persistence.
- **Menus:** allergen and dietary information must be explicitly supplied.
  Filtering is presentation behavior; it does not infer ingredients or
  determine suitability.
- **Frameworks:** components stay router-independent and work in Next.js and
  TanStack Start using their normal React client boundaries for interactions.

## Composition guidance

Use one component for each distinct responsibility. `LocationSection` describes
the venue; `LocalGuideSection` describes nearby places. `TestimonialsSection`
handles generic quotes; `GuestReviewsSection` adds dated review metadata and a
supplied score summary. `TeamSection` is for multiple people;
`HostProfileSection` is a single host. `ServicesSection` handles general
services; `ServiceOptionsSection` adds included/optional labels.
