These application-oriented Pieces help teams browse, select, and describe existing media. They compose the UI package's tree, table, upload, image-editing, and overlay components; they do not provide a storage service, CMS, router, or network client.

**Scope:** all data and actions come from the caller. Selection and form values are asset IDs. A preview is shown only when the caller provides an authorized, temporary preview URL.

## Components

| Component | Purpose | Reference |

## Safe browser data

Pass a `MediaLibraryAsset` projection rather than a storage-domain record. The projection deliberately does not include storage object keys, tenant or audit internals, processing errors, or server-only data. `previewUrl` and variant preview URLs are caller-supplied ephemeral authorized image/poster URLs; Pieces never creates, refreshes, stores, or derives them.

Selection and reference callbacks use asset IDs. Applications should map IDs to their own records, authorize each preview request, and keep persistence and permission checks on their server.

## Composition and accessibility

`MediaLibrary` reuses UI `TreeView`, `DataTable`, `Autocomplete`, `Image`, `MediaFrame`, `ImageUpload`, `VideoUpload`, and `FileUpload`. `AssetPickerDialog` composes UI `Dialog` and `Drawer`; `AssetDetailsPanel` uses `ImageBox`, `ImageCropper`, and `ImageHotspotEditor`. Do not add a competing uploader, tree, table, or dialog around these Pieces.

Interactive pieces are client components. Keep the containing boundary client-side when using a framework with server components. Native controls, visible keyboard focus, UI overlay keyboard behavior, and mobile layouts are provided; applications still own validation policy, authorization, upload transport, metadata persistence, and conflict handling.
