`LogoCloudSection` presents consumer-provided logo collections. Each item must have a stable ID, name, and alt text, and must provide either an image `src` or a custom `logo` node.

<Badge content="Beta" color="primary" /> **API maturity: Beta.**

## Installation

```tsx
import { LogoCloudSection, type LogoCloudItem } from "@puzzle-ui/pieces";
```

## Variant previews

The marquee is scrollable and intentionally motion-free. The carousel includes labeled controls and supports left/right arrow keys when its navigation group is focused.

Letter marks use the logo color as their fill. The dark variant uses a contrasting letter color in both light and dark themes.

## API

| Prop | Type | Description |
| --- | --- | --- |
| `variant` | `LogoCloudVariant` | Selects one of the twelve logo compositions; defaults to `grid`. |
| `logos` | `readonly LogoCloudItem[]` | Logo data. `LogoCloudItem` requires `id`, `name`, and `alt`, plus either `src` or `logo`. |
| `group` | `string` on each item | Groups logos when `variant="grouped"`. |
| `featured` | `boolean` on each item | Emphasizes an item in the `featured` layout. |
| `href` | `string` on each item | Optional destination for a logo. |
| Shared section props | `SectionRootProps` and heading props | Semantic root, theme, native attributes, heading, actions, and children. |


### Required and default values

Requiredness follows the exported TypeScript type. A dash means no component-level default is applied; variant-specific requirements are described in the API table above.

| Prop | Required | Default |
| --- | --- | --- |
| `variant` | No | `"grid"` |
| `logos` | Yes | — |
## Usage

```tsx
<LogoCloudSection
  variant="grouped"
  title="Our partners"
  logos={[
    {
      id: "acme",
      name: "Acme",
      alt: "Acme logo",
      src: "/logos/acme.svg",
      group: "Technology",
      href: "/partners/acme",
    },
  ]}
/>
```

Custom logo nodes are wrapped in an image role using the supplied `alt` text. Image sources are lazy-loaded. Empty collections render no list; the optional heading remains available.

## Accessibility

Provide an accurate `alt` for every logo. A linked logo uses the supplied `name` as its link name. The carousel has named previous/next buttons and an arrow-key-operable group. No carousel or marquee autoplay is enabled.

## Customization

Use the component's `className` and documented slots to adapt the composition. Prefer a caller-provided `ReactNode` for media, actions, or controls rather than adding domain behavior to the section.

```tsx
import type { ComponentProps } from "react";
import { LogoCloudSection } from "@puzzle-ui/pieces";

type LogoCloudSectionProps = ComponentProps<typeof LogoCloudSection>;

export function CustomizedSection(props: LogoCloudSectionProps) {
  return <LogoCloudSection {...props} className={[props.className, "brand-section"].filter(Boolean).join(" ")} />;
}
```

## Responsive behavior

Use the preview device selector to review mobile, tablet, and desktop widths. The built-in variant controls section structure; ensure application-provided media, form controls, and children can shrink or wrap without horizontal overflow. Use the existing responsive breakpoints in scoped CSS when the consuming layout needs a product-specific adjustment.

## Theme support

The section consumes semantic variables from `@puzzle-ui/theme` and inherits active or scoped themes. Wrap the application with `Theme`, and use semantic roles such as text, surface, border, and primary for local overrides. Avoid hard-coded colors, spacing, radii, and shadows.

```css
.brand-section {
  color: var(--puzzle-color-text);
  background: var(--puzzle-color-surface);
  border-color: var(--puzzle-color-border);
}
```

## Composition

Compose this section with the UI primitives named in its API and use the documented slots for consumer-owned controls or media. Keep data fetching, routing, validation, permissions, and persistence in the application. The `children` slot is intended for additional content that belongs with this section, not as a substitute for its typed data model.

## TypeScript example

The package exports this component from its root. Derive a wrapper's exact prop type from the public component rather than widening it:

```tsx
import type { ComponentProps } from "react";
import { LogoCloudSection } from "@puzzle-ui/pieces";

type LogoCloudSectionProps = ComponentProps<typeof LogoCloudSection>;

export function SectionWrapper(props: LogoCloudSectionProps) {
  return <LogoCloudSection {...props} />;
}
```
