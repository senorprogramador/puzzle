Settings compositions provide layout and semantic structure only. Data loading, validation, and mutations remain in the application.

<Badge content="Stable" color="primary" /> **API maturity: Stable.** The documented API is covered by package tests and is intended to remain backward-compatible within a major version. This is an API commitment, not a guarantee of production readiness in every application.

## Installation

```tsx
import {
  FormActions,
  ProfileHeader,
  SecurityMethodCard,
  SettingsGroup,
  SettingsRow,
  SettingsSection,
} from "@puzzle-ui/pieces";
```

## Sections and rows

Use `SettingsSection` for a labelled settings area and `SettingsGroup` to organize related rows. Associate each form control with its label through `htmlFor` and the control's `id`.

## Interactive tabs and preferences

The settings layout does not own application state. Compose it with UI `Tabs`, `Switch`, and other controls; the application supplies their values and change handlers.

## Accessibility and responsive behavior

- Sections and groups are labelled by their headings.
- Supply `htmlFor` and matching control IDs for form labels. Row descriptions and errors are associated with a single control element when possible.
- Error messages use an alert announcement; the consuming application remains responsible for validation and state.
- Settings state, persistence, and validation rules remain in the application.
- Layouts stack on narrow viewports and use Puzzle theme tokens.

## API

| Component            | Props                                                                                                                |
| -------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `SettingsSection`    | `title` and `children` (required), `description`, `actions`, `navigation`, `navigationLabel`, `variant`, `className` |
| `SettingsGroup`      | `children` (required), `title`, `className`                                                                          |
| `SettingsRow`        | `label`, `control` (required), `description`, `error`, `htmlFor`, `className`                                        |
| `FormActions`        | `children` (required), `className`                                                                                   |
| `ProfileHeader`      | `name` (required), `email`, `avatar`, `actions`, `className`                                                         |
| `SecurityMethodCard` | `title` (required), `description`, `status`, `icon`, `action`, `className`                                           |

### Required and default values

Requiredness follows the exported TypeScript type. A dash means no component-level default is applied; variant-specific requirements are described in the API table above.

| Prop              | Required | Default                 |
| ----------------- | -------- | ----------------------- |
| `title`           | Yes      | —                       |
| `description`     | No       | —                       |
| `actions`         | No       | —                       |
| `navigation`      | No       | —                       |
| `navigationLabel` | No       | `"Settings navigation"` |
| `variant`         | No       | `"grouped"`             |
| `children`        | Yes      | —                       |
| `className`       | No       | —                       |

## Customization

Use the component's `className` and documented slots to adapt the composition. Prefer a caller-provided `ReactNode` for media, actions, or controls rather than adding domain behavior to the section.

```tsx
import type { ComponentProps } from "react";
import { SettingsSection } from "@puzzle-ui/pieces";

type SettingsSectionProps = ComponentProps<typeof SettingsSection>;

export function CustomizedSection(props: SettingsSectionProps) {
  return (
    <SettingsSection
      {...props}
      className={[props.className, "brand-section"].filter(Boolean).join(" ")}
    />
  );
}
```

## Theme support

The section consumes semantic variables from `@puzzle-ui/theme` and inherits active or scoped themes. Wrap the application with `Theme`, and use semantic roles such as text, surface, border, and primary for local overrides. Avoid hard-coded colors, spacing, radii, and shadows.

```css
.brand-section {
  color: var(--puzzle-color-text);
  background: var(--puzzle-color-surface);
  border-color: var(--puzzle-color-border);
}
```

## Composition

Compose this section with the UI primitives named in its API and use the documented slots for consumer-owned controls or media. Keep data fetching, routing, validation, permissions, and persistence in the application. The `children` slot is intended for additional content that belongs with this section, not as a substitute for its typed data model.

## TypeScript example

The package exports this component from its root. Derive a wrapper's exact prop type from the public component rather than widening it:

```tsx
import type { ComponentProps } from "react";
import { SettingsSection } from "@puzzle-ui/pieces";

type SettingsSectionProps = ComponentProps<typeof SettingsSection>;

export function SectionWrapper(props: SettingsSectionProps) {
  return <SettingsSection {...props} />;
}
```

## Framework compatibility

The section is router-independent. Static compositions can be server-rendered; place callback-driven interactions in the framework's client boundary. See [Next.js and TanStack Start integration](/docs/pieces/framework-integration) for runnable framework examples and SSR guidance.
