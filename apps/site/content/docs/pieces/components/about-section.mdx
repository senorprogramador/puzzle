`AboutSection` combines company information and story content into a responsive introduction. Supply only the content that is relevant to your organization; empty collections are omitted.

<Badge content="Beta" color="primary" /> **API maturity: Beta.**

## Installation

```tsx
import {
  AboutSection,
  type AboutSectionProps,
  type AboutSectionVariant,
} from "@puzzle-ui/pieces";
```

## API

| Prop | Type | Description |
| --- | --- | --- |
| `variant` | `AboutSectionVariant` | `split` (default), `centered`, `editorial`, `image-led`, `story`, `timeline`, `stats`, `team`, `mission`, `values`, `asymmetric`, or `full-width`. |
| `company` | `CompanyInfoProps` without `className` | Optional company name, logo, tagline, description, and native website link. |
| `story` | `AboutStory` | Story description, optional title, and optional editorial image. |
| `mission`, `vision` | `ReactNode` | Purpose statements, shown when provided. |
| `images` | `readonly EditorialImage[]` | Supporting images with alt text and optional captions. |
| `stats` | `readonly BusinessMetricItem[]` | Stable IDs, labels, values, and optional descriptions. |
| `values` | `readonly BusinessValue[]` | Values with stable IDs, titles, optional descriptions, and decorative icons. |
| `timeline` | `readonly BusinessTimelineItem[]` | Milestones with stable IDs, year, title, and optional description. |
| `team` | `readonly BusinessProfile[]` | Optional profiles for the `team` composition. |
| Shared section props | `MarketingSectionBaseProps` | Heading, actions, root element, native section attributes, and children. |


### Required and default values

Requiredness follows the exported TypeScript type. A dash means no component-level default is applied; variant-specific requirements are described in the API table above.

## Usage

```tsx
<AboutSection
  variant="mission"
  eyebrow="About Northstar"
  title="Make meaningful progress."
  description="An independent partner for complex change."
  mission="Make complex change manageable for every team."
  vision="Build a more resilient, thoughtful future."
  values={[
    { id: "care", title: "Care", description: "Start with people." },
    { id: "clarity", title: "Clarity", description: "Make the complex useful." },
  ]}
/>
```

## Content and accessibility

All data is supplied by the application; the component does not fetch company information. Provide meaningful alt text for informative images and empty alt text for decorative images. Timelines and value collections use semantic lists, metrics use a description list, and profile links remain native anchors. The section renders on the server.

## Customization

Use the component's `className` and documented slots to adapt the composition. Prefer a caller-provided `ReactNode` for media, actions, or controls rather than adding domain behavior to the section.

```tsx
import type { ComponentProps } from "react";
import { AboutSection } from "@puzzle-ui/pieces";

type AboutSectionProps = ComponentProps<typeof AboutSection>;

export function CustomizedSection(props: AboutSectionProps) {
  return <AboutSection {...props} className={[props.className, "brand-section"].filter(Boolean).join(" ")} />;
}
```

## Responsive behavior

Use the preview device selector to review mobile, tablet, and desktop widths. The built-in variant controls section structure; ensure application-provided media, form controls, and children can shrink or wrap without horizontal overflow. Use the existing responsive breakpoints in scoped CSS when the consuming layout needs a product-specific adjustment.

## Theme support

The section consumes semantic variables from `@puzzle-ui/theme` and inherits active or scoped themes. Wrap the application with `Theme`, and use semantic roles such as text, surface, border, and primary for local overrides. Avoid hard-coded colors, spacing, radii, and shadows.

```css
.brand-section {
  color: var(--puzzle-color-text);
  background: var(--puzzle-color-surface);
  border-color: var(--puzzle-color-border);
}
```

## Composition

Compose this section with the UI primitives named in its API and use the documented slots for consumer-owned controls or media. Keep data fetching, routing, validation, permissions, and persistence in the application. The `children` slot is intended for additional content that belongs with this section, not as a substitute for its typed data model.

## TypeScript example

The package exports this component from its root. Derive a wrapper's exact prop type from the public component rather than widening it:

```tsx
import type { ComponentProps } from "react";
import { AboutSection } from "@puzzle-ui/pieces";

type AboutSectionProps = ComponentProps<typeof AboutSection>;

export function SectionWrapper(props: AboutSectionProps) {
  return <AboutSection {...props} />;
}
```
