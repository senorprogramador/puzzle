`ContentTypeBuilder` edits the controlled identity, version, locale list, and ordered fields of a CMS content type. It performs local field-key checks and leaves registration, migration compatibility, and authoritative schema validation to the CMS service.

</Preview>

## API

| Prop | Type | Required | Default |
|---|---|---:|---|
| `value` | `ContentTypeDefinition` | Yes | — |
| `onChange` | `(definition: ContentTypeDefinition) => void` | Yes | — |
| `onSave` | `() => void \| Promise<void>` | No | — |
| `renderFieldSettings` | `(field, index, onChange) => ReactNode` | No | — |
| `saving` / `disabled` | `boolean` | No | `false` |
| `className` | `string` | No | — |

The built-in editor adds, removes, reorders, and edits field keys, labels, types, required/localized flags, content type name/slug/version, and locale identifiers. Use `renderFieldSettings` to expose select options, relationship targets, nested repeater/block definitions, defaults, and validation rules.

```tsx
import { ContentTypeBuilder } from "@puzzle-ui/pieces";

<ContentTypeBuilder
  value={definition}
  onChange={setDefinition}
  onSave={() => registerTypeOnServer(definition)}
/>;
```

Renaming/removing fields or changing types can require a version migration. Do not treat the local key feedback as permission to persist a breaking schema; use the CMS migration and revision contracts on the server.
