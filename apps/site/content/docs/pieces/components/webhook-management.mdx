`WebhookManagement` presents sanitized CMS webhook subscriptions and delivery
history. Use it with an application-owned client and workers, not as a delivery
service or authorization boundary.

## API

| Prop | Purpose |
|---|---|
| `subscriptions`, `eventTypes` | Authorized subscription projections and supported event names. |
| `deliveries`, `deliverySubscriptionId` | Deliveries and the subscription they belong to; stale data for another selection is hidden. |
| `attemptsByDelivery`, `onRequestAttempts` | Optional attempt history and caller-owned loading callback. |
| `onSelectSubscription` | Load authorized deliveries for the selected subscription. |
| `onCreate`, `onUpdate` | Persist values and return the saved sanitized subscription; updates include the expected revision and rotation request. |
| `onRetry` | Retry a failed delivery using its expected revision. |
| `onDirtyChange` | Track unsaved form state for host-router and unload guards. |
| `loading`, `error`, `className` | Loading/error presentation and custom styling. |

Existing subscribed events remain available in the editor even if omitted from
`eventTypes`, so they can be removed or reselected before saving.

The browser CMS client provides `listWebhookSubscriptions`,
`getWebhookSubscription`, `createWebhookSubscription`,
`updateWebhookSubscription`, `listWebhookDeliveries`, `listWebhookAttempts`,
and `retryWebhookDelivery`. Map the component callbacks to these methods using
their documented revision inputs; the client contracts contain only sanitized
projections, never secret references.

```tsx
import { WebhookManagement } from "@puzzle-ui/pieces";
```

The host controls all fetching, authorization, validation, secret provisioning,
and background delivery. Never pass signing secrets or secret references.
Rotation is a request to the host, not a secret input. Handle stale responses
and display sanitized errors; callbacks may reject to show an error without
discarding the draft. The component confirms before switching away from a dirty
form, but the host must guard navigation and page unload using `onDirtyChange`.

## Accessibility and responsive behavior

Native labeled controls and a confirmation dialog support keyboard use. Status
and failure information is textual rather than color-only, and long endpoints
wrap at narrow widths.
