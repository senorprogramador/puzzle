Use the React TextInput component for single-line form fields, including search, email addresses, phone numbers, and passwords. It adds theme styling and optional affixes while keeping the underlying native input behavior.

<Badge content="Stable" color="primary" /> **API maturity: Stable.** The documented public API is covered by tests and is intended to remain backward-compatible within a major version. This is an API commitment, not a guarantee of production readiness in every application.


## Import

```tsx
import { TextInput } from "@puzzle-ui/ui";
```

## Types and affixes

`email` and `phone` provide default leading icons; `phone` renders a native `tel` input. `search` renders a native search input. Password fields include a show/hide button. Explicit `prefix` or `suffix` replaces the default affix; `null` removes it.

## API

| Prop                    | Type                                         | Default       | Description                                    |
| ----------------------- | -------------------------------------------- | ------------- | ---------------------------------------------- |
| `type`                  | `"text" \| "email" \| "password" \| "phone" \| "search"` | `"text"`      | Input purpose.                                 |
| `prefix`, `suffix`      | `ReactNode`                                  | Type-specific | Leading and trailing content.                  |
| `value`, `defaultValue` | Native input value                           | -             | Controlled or initial value.                   |
| `onChange`              | `ChangeEventHandler<HTMLInputElement>`       | -             | Native change event.                           |
| `disabled`              | `boolean`                                    | `false`       | Disables input and password visibility button. |
| `className`             | `string`                                     | -             | Class on the outer span.                       |

Other native input attributes and `ref` apply to the input. Prefix content is decorative and hidden from assistive technology; keep essential units or instructions in the label/description. Always provide a label.

## Accessibility and keyboard behavior

Use semantic content and provide accessible names for interactive controls. Native controls retain browser keyboard behavior; any custom interaction should be verified with a keyboard and assistive technology in your application. This API maturity label is not an accessibility certification.

**Framework compatibility:** The UI package declares React and React DOM 19 as peers. Components do not require a router; framework-specific and server-rendering compatibility are not guaranteed, so verify behavior in your target framework.
