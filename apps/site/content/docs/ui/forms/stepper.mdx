Stepper shows progress through a sequence. It does not render panels or validate a form: your application owns the content and the rules for advancing.

## Import

```tsx
import { Stepper } from "@puzzle-ui/ui";
```

## Basic usage

Compose direct `Stepper.Step` children. Steps before the active step are completed automatically. Stable IDs preserve selection when steps are reordered; every step needs a unique ID in ID-based mode, and the active ID must match an available step.

<Preview
  hideDevices={true}
  code={`\
<Stepper defaultActiveStepId="shipping" aria-label="Checkout progress">
  <Stepper.Step id="details" label="Details" />
  <Stepper.Step id="shipping" label="Shipping" />
  <Stepper.Step id="payment" label="Payment" />
</Stepper>
`}
>
  <Section>
    <Stepper defaultActiveStepId="shipping" aria-label="Checkout progress">
      <Stepper.Step id="details" label="Details" />
      <Stepper.Step id="shipping" label="Shipping" />
      <Stepper.Step id="payment" label="Payment" />
    </Stepper>
  </Section>
</Preview>

## Orientation and supporting text

`orientation` accepts `"horizontal"`, `"vertical"`, or a responsive object. Use `description` for supporting text and `optional` to identify a non-required step. Change device sizes to see the layout switch.

<Preview
  code={`\
<Stepper
  orientation={{ mobile: "vertical", tablet: "horizontal" }}
  defaultActiveStep={1}
>
  <Stepper.Step label="Details" description="Your contact information" />
  <Stepper.Step label="Shipping" description="Delivery address" />
  <Stepper.Step label="Gift note" optional="Optional" />
</Stepper>
`}
>
  <Section>
    <Stepper
      orientation={{ mobile: "vertical", tablet: "horizontal" }}
      defaultActiveStep={1}
    >
      <Stepper.Step label="Details" description="Your contact information" />
      <Stepper.Step label="Shipping" description="Delivery address" />
      <Stepper.Step label="Gift note" optional="Optional" />
    </Stepper>
  </Section>
</Preview>

## Clickable and non-linear steps

`clickable` turns selectable steps into buttons. By default, `linear` allows only the current and earlier steps to be selected. Set `linear={false}` to allow navigation to future steps; `disabled` still prevents selection.

<Preview
  hideDevices={true}
  code={`\
<Stepper clickable linear={false} defaultActiveStepId="details" orientation="vertical">
  <Stepper.Step id="details" label="Details" />
  <Stepper.Step id="shipping" label="Shipping" />
  <Stepper.Step id="payment" label="Payment" disabled description="Not available yet" />
</Stepper>
`}
>
  <Section>
    <Stepper
      clickable
      linear={false}
      defaultActiveStepId="details"
      orientation="vertical"
    >
      <Stepper.Step id="details" label="Details" />
      <Stepper.Step id="shipping" label="Shipping" />
      <Stepper.Step
        id="payment"
        label="Payment"
        disabled
        description="Not available yet"
      />
    </Stepper>
  </Section>
</Preview>

## Completed, error, and custom icons

`completed` overrides automatic completion. `error` takes precedence over other visual states. `icon` replaces the numeric or state indicator; keep the visible `label` meaningful because the indicator is hidden from assistive technology.

<Preview
  hideDevices={true}
  code={`\
<Stepper defaultActiveStep={1} orientation="vertical">
  <Stepper.Step label="Account" completed icon={<Icon name="akar-icons:check" size={20} />} />
  <Stepper.Step label="Address" error description="Add a valid postal code to continue." />
  <Stepper.Step label="Payment" completed={false} optional="Choose a method later" />
</Stepper>
`}
>
  <Section>
    <Stepper defaultActiveStep={1} orientation="vertical">
      <Stepper.Step

      />

        label="Payment"
        completed={false}

  </Section>
</Preview>

## Controlled progress

Use `activeStep` with `onStepChange` for zero-based index selection. An external Continue action can advance progress while clickable steps allow returning to completed work. ID-based controlled selection uses `activeStepId` with `onStepIdChange` instead; do not mix the two modes.

<Preview hideDevices={true} code={`\
const [activeStep, setActiveStep] = useState(0);

return (

  <Stack>
    <Stepper activeStep={activeStep} onStepChange={setActiveStep} clickable>
      <Stepper.Step label="Details" />
      <Stepper.Step label="Shipping" />
      <Stepper.Step label="Payment" />
    </Stepper>
    <Stack direction="row">
      <Button variant="outline" disabled={activeStep === 0} onClick={() => setActiveStep(activeStep - 1)}>Back</Button>
      <Button disabled={activeStep === 2} onClick={() => setActiveStep(activeStep + 1)}>Continue</Button>
    </Stack>
    <span role="status">Step {activeStep + 1} of 3</span>
  </Stack>
);
`}>
  <Section><ControlledStepperExample /></Section>
</Preview>

## API

### Stepper

| Prop                  | Type                                          | Default        | Description                                                              |
| --------------------- | --------------------------------------------- | -------------- | ------------------------------------------------------------------------ |
| `children`            | `ReactNode`                                   | Required       | Direct `Stepper.Step` children.                                          |
| `activeStep`          | `number`                                      | -              | Controlled zero-based index, clamped to available steps.                 |
| `defaultActiveStep`   | `number`                                      | `0`            | Initial uncontrolled index.                                              |
| `onStepChange`        | `(step: number) => void`                      | -              | Next index after user selection, including in ID mode.                   |
| `activeStepId`        | `string \| number`                            | -              | Controlled stable ID; must match an available step.                      |
| `defaultActiveStepId` | `string \| number`                            | -              | Initial uncontrolled stable ID.                                          |
| `onStepIdChange`      | `(stepId: string \| number) => void`          | -              | Next ID after selection in ID mode.                                      |
| `orientation`         | `ResponsiveValue<"horizontal" \| "vertical">` | `"horizontal"` | Layout direction; responsive keys are `mobile`, `tablet`, and `desktop`. |
| `clickable`           | `boolean`                                     | `false`        | Renders step buttons for navigation.                                     |
| `linear`              | `boolean`                                     | `true`         | Prevents selecting steps ahead of the active one.                        |
| `className`           | `string`                                      | -              | Additional class on the root ordered list.                               |
| `dir`                 | `"ltr" \| "rtl" \| "auto"`                    | -              | Root direction; explicit `rtl` reverses horizontal keyboard navigation.  |

Other native ordered-list attributes are forwarded to the root.

### Stepper.Step

| Prop          | Type               | Default            | Description                                           |
| ------------- | ------------------ | ------------------ | ----------------------------------------------------- |
| `id`          | `string \| number` | -                  | Stable identifier; required on every step in ID mode. |
| `label`       | `ReactNode`        | Required           | Visible step label.                                   |
| `description` | `ReactNode`        | -                  | Supporting text beneath the label.                    |
| `optional`    | `ReactNode`        | -                  | Additional optional-step text.                        |
| `icon`        | `ReactNode`        | -                  | Custom indicator content.                             |
| `completed`   | `boolean`          | Before active step | Overrides automatic completion.                       |
| `error`       | `boolean`          | `false`            | Displays an error state.                              |
| `disabled`    | `boolean`          | `false`            | Prevents navigation to this step.                     |
| `className`   | `string`           | -                  | Additional class on the step list item.               |

## Accessibility

Clickable steps use roving focus: arrow keys move focus (in either orientation), Home and End move to the first and last selectable step, and Enter or Space activates the focused step. With the default `linear` behavior, steps ahead of the active step cannot be selected.

The active list item exposes `aria-current="step"`. Give the ordered list a descriptive `aria-label` when there are multiple progress indicators.

**Framework compatibility:** The UI package declares React and React DOM 19 as peers. Components do not require a router; framework-specific and server-rendering compatibility are not guaranteed, so verify behavior in your target framework.
