`@puzzle-ui/auth` is the server-side authentication core for Puzzle. It provides storage-backed registration and sign-in, account lifecycle workflows, multi-factor authentication, passkeys, recovery codes, and step-up verification without coupling those features to a web framework.

The package accepts storage, session, password-hashing, email, rate-limit, secret-protection, and WebAuthn dependencies through explicit interfaces. Your application remains responsible for creating secure HTTP endpoints, managing cookies and CSRF, and deciding what authenticated users may do.

`@puzzle-ui/auth` depends on `@puzzle-ui/storage`, `@puzzle-ui/session`, and `@simplewebauthn/server`. You provide the storage and session implementations, password hasher, and rate-limit provider.

## Quick start

Create a manager with server-side dependencies, initialize it before serving requests, and keep the returned token on the server boundary so it can be set in a secure, HttpOnly cookie.

```ts
import { StorageAuthManager } from "@puzzle-ui/auth";

const auth = new StorageAuthManager(
  { storage, passwordHasher, rateLimitProvider, sessions },
  { rateLimitKeySecret },
);

await auth.initialize();

const result = await auth.register({
  email: "person@example.com",
  password: "a-long-unique-password",
  ipAddress: trustedClientIp,
});

if ("status" in result) {
  // MFA is required; complete the enrollment flow on the server.
} else {
  // Set result.token in a secure, HttpOnly cookie. Do not return it in JSON.
}
```

The `StorageAuthManager` creates an authenticated session after registration unless policy requires an MFA enrollment first. A password sign-in can return an MFA challenge instead of a session. See [MFA and step-up](/docs/auth/mfa) for how to complete these flows.

## Authentication states

`getAuthState(token)` reports the server-side state for an authentication or pending challenge token. Treat only `authenticated` as normal application access.

| Status | Meaning |
| --- | --- |
| `unauthenticated` | No valid authenticated session or pending challenge was found. |
| `primary-authenticated` | A staged-auth state represented in the public state type; it is not returned by the core manager. Do not treat it as full access. |
| `mfa-pending` | Password authentication succeeded and an enrolled factor must be verified. |
| `mfa-enrollment-pending` | Policy requires initial enrollment; no normal session is issued yet. |
| `mfa-enrollment-required` | A valid session exists, but policy requires a factor before protected access. |
| `authenticated` | The session is valid and satisfies the configured email-verification and MFA policy. |

Challenge tokens, like session tokens, are credentials. Keep them server-side and transport them only in appropriately scoped secure, HttpOnly cookies.

## Integrating packages

- [`@puzzle-ui/storage`](/docs/storage) provides the adapter used to persist users, credentials, audit records, challenges, recovery codes, and rate-limit counters. Authentication requires the storage capabilities described in [Security](/docs/auth/security).
- [`@puzzle-ui/fullstack`](/docs/fullstack) provides server handlers, browser clients, cookie and CSRF integration, and framework adapters. The [developer authentication guide](/docs/developer/authentication) covers generated application setup.
- Auth also stores authentication audit events; keep credentials and secret values out of logs and telemetry.
