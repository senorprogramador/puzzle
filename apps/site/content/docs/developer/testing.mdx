Puzzle uses several test runners depending on the package and the type of behavior being tested.

The repository includes:

- Vitest for unit and component tests.
- Node's test runner for several server-side packages.
- Playwright-backed browser tests through Vitest.
- Docker Compose for MongoDB integration tests.

## Install dependencies

From the repository root:

```bash
bun install
```

## Run the repository test command

The root `test:all` script builds the packages first, runs package test scripts, runs the project generator tests, and runs the UI and Pieces browser tests.

```bash
bun run test:all
```

This is the broadest standard test command in the repository. It also runs MongoDB integration tests; Docker Compose and Playwright Chromium are required.

## Package-specific tests

### UI components

Run unit and component tests:

```bash
bun run --filter "@puzzle-ui/ui" vitest
```

Run only unit tests:

```bash
bun run --filter "@puzzle-ui/ui" test:unit
```

Run only component tests:

```bash
bun run --filter "@puzzle-ui/ui" test:component
```

Run browser tests:

```bash
bun run --filter "@puzzle-ui/ui" test:browser
```

### Pieces

```bash
bun run --filter "@puzzle-ui/pieces" vitest
bun run --filter "@puzzle-ui/pieces" test:browser
```

### Project generator

```bash
bun run --filter "@puzzle-ui/create" test
```

### Generated project end-to-end tests

The project generator has an end-to-end suite that creates every framework, Tailwind, Auth and database combination in a temporary directory. Each project is installed with Bun using the local `@puzzle-ui/*` packages, then:

- builds and typechecks
- downloads its local fonts
- serves the production build

For MongoDB and D1 projects, the suite also runs the sign-up, sign-out and sign-in flows against the running app.

```bash
bun run test:e2e
```

Docker with Compose and network access are required. The suite builds the workspace first and removes the generated projects, containers and volumes when it finishes. Set `PUZZLE_E2E_FILTER` to run specific projects, for example `PUZZLE_E2E_FILTER=tanstack-auth-d1 bun run test:e2e`. See the [create package README](https://github.com/senorprogramador/puzzle/tree/main/packages/create#end-to-end-tests) for all options.

Run it when changing the generator, its templates, or packages used by generated projects.

### Fullstack Auth, media, and CMS APIs

Run server-side and unit tests:

```bash
bun run --filter "@puzzle-ui/fullstack" test
```

Run browser tests:

```bash
bun run --filter "@puzzle-ui/fullstack" test:browser
```

After building workspace packages, run the CMS and Media browser journeys in
temporary copies of the Next.js and TanStack Workspace examples:

```bash
bun run build
bun run --filter "@puzzle-ui/fullstack" test:e2e:frameworks
```

These tests need Playwright Chromium and the installed Workspace app
dependencies. They add test-only routes and an in-memory service fixture to
each copy, stub the unrelated Workspace auth-state request, and use a
synthetic processor that copies bytes rather than performing real transcoding.
They do not change production app routes or validate a production provider.

### Authentication and storage

Several backend packages use Node's built-in test runner.

```bash
bun run --filter "@puzzle-ui/auth" test
bun run --filter "@puzzle-ui/session" test
bun run --filter "@puzzle-ui/storage" vitest
bun run --filter "@puzzle-ui/storage-d1" test
```

### Media and CMS domains

Run the provider-neutral contract and domain-service tests:

```bash
bun run --filter "@puzzle-ui/media" test
bun run --filter "@puzzle-ui/cms" test
```

The media package also exercises its browser-only image/video helpers in
Chromium:

```bash
bun run --filter "@puzzle-ui/media" test:browser
```

Playwright Chromium must be installed for this check.

## MongoDB integration tests

The MongoDB storage adapter uses a dedicated test runner.

```bash
bun run --filter "@puzzle-ui/storage-mongodb" test
```

Docker with Compose must be available. The test script starts its MongoDB test environment on a free localhost port, so a MongoDB already running on port 27017 does not conflict (set `MONGODB_TEST_PORT` to choose the port), and cleans up the container and volume when it finishes.

## Type checking

Run type checks for all packages and the documentation site:

```bash
bun run typecheck
```

Run the documentation site's type check independently:

```bash
bun run --filter "@puzzle-ui/site" typecheck
```

## Build checks

Build all packages:

```bash
bun run build
```

Build the documentation site:

```bash
bun run --filter "@puzzle-ui/site" build
```

The site build also validates its MDX pages and documentation examples.

## Browser test requirements

Browser tests require the Playwright Chromium browser to be installed.

If a browser test fails before reaching the test assertions, verify the Playwright browser installation and the local browser dependencies first.

## Recommended workflow

For a component change:

1. Run the component's unit tests.
2. Run its component tests.
3. Run its browser tests if keyboard, pointer, focus, or other browser behavior changed.
4. Run the package type check.
5. Build the package.

For a documentation change:

1. Verify all imports and links.
2. Run the site type check.
3. Build the documentation site.

For documentation navigation changes, run the source-derived inventory tests
and production browser checks:

```bash
bun run --filter "@puzzle-ui/site" test:navigation
bun run --filter "@puzzle-ui/site" build
bun run --filter "@puzzle-ui/site" test:navigation:browser
```

The navigation checks cover every Markdown and MDX route, unique links and IDs,
source page titles, active ancestors, category links, keyboard interaction,
mobile dismissal, search, canonical breadcrumbs, and sitemap coverage.
The browser check requires Playwright Chromium and serves the production output
on a temporary local port. Set `PUZZLE_NAVIGATION_SCREENSHOT_DIR` to capture
desktop and mobile navigation with light and dark Theme tokens. The documentation
shell currently uses light mode; the check applies the public Theme's dark
styles temporarily to verify token compatibility, not a site theme switch.

To compare a refactor against an original inventory, set
`PUZZLE_NAVIGATION_BASELINE` to a JSON file with `pages` (`path`, `url`, `title`)
and `entries` (`id`, optional `href`) arrays. Capture it before changing the
navigation; the browser check verifies that source routes, page titles, IDs,
and existing link destinations remain unchanged.

For changes to the documentation component catalog, run the production browser
check across mobile, tablet, and desktop viewport widths:

```bash
bun run --filter "@puzzle-ui/site" test:catalog:responsive
```

This checks catalog routes, the 1/2/3-column layout, horizontal overflow,
semantic links, and visible keyboard focus. Build the site first; the check
serves the generated production output.

For changes affecting shared packages or public APIs, run the broader repository checks.
